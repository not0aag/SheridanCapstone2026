# Communication Channels & Norms

This document outlines our team communication setup for Phase 1.

## Primary Channels

- Slack (preferred) or Discord (backup)
- GitHub Issues/PRs for technical discussions tied to code
- Notion/Google Drive for meeting notes and artifacts

## Slack Workspace (recommended)

- Channels:
  - #announcements — PM updates, releases, key notices (read-only for PM)
  - #general — cross-team updates, quick questions
  - #mobile — mobile app development
  - #ml — ML/AI research and models
  - #backend — API, database, video pipeline
  - #infra — deployment, CI/CD, AWS
  - #demo — assets, scripts, and coordination
- Naming conventions: kebab-case, clear scope
- Etiquette:
  - Prefer threads; summarize conclusions in the main thread
  - Use @here/@channel sparingly
  - Declare blockers early with a short context and ask

## Meetings

- Stand-up: Mondays 09:00 (30 min)
- Friday Review: Fridays 16:00 (1 hr)
- See `../schedule/meetings.md` and ICS templates to import recurring events

## Decisions & Docs

- Decisions captured in Notion/Drive and referenced from PRs/issues
- Major design changes require a short ADR (Architecture Decision Record)

## Incident Communication

- High-severity issues: notify in #announcements and page relevant owner(s)
- Keep a concise incident summary with timeline and outcome
